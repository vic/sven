A yen module looks like a NixOS module: a path, a function or an attrset, with `imports`. It is not one.
yen does not use the NixOS module system and does not depend on nixpkgs: it uses Nix builtins only.
A module is a function `sources -> sinks`, as in Cycle. Its keys:

- `imports`: more yen modules.
- `yen`: every declaration.
- any other key: a module sink, such as `lib` or `inputs`. Any module reads a sink as an arg.

There is no `options` and no `config`. A sink that no module reads or declares is an error. So is a
key that yen does not read inside `yen` or inside a kind:


```nix title="variants/nixos-style.nix"
# A NixOS module, as people write them. yen reads none of it, and says so.
{
  options.services.web.enable = true;
  config.services.web.enable = true;
}
```

```nix title="result"
[
  {
    code = "unread-sink";
    error = "no module reads the sink `config`";
    path = [
      "config"
    ];
  }
  {
    code = "unread-sink";
    error = "no module reads the sink `options`";
    path = [
      "options"
    ];
  }
]
```

## Module sinks: the options of a module

`yen.sinks.<name>` declares a module sink, as a top-level `options` does in NixOS. Its keys are the
keys of a kind's sink: `of` is the type that checks each module's value, and `reduce` is the merge
strategy. A sink with no `reduce` takes `one` value, which an arg gets as it is. A declared sink that
no module gives reduces to its empty value.


```nix title="variants/module-sinks.nix"
# NixOS top-level `options` become module sinks. `yen.sinks` declares one: `of` checks each module's value,
# `reduce` merges the values. Any module reads the sink as an arg.
{ yen, ... }:
{
  yen.sinks.admins = {
    of = yen.lib.is builtins.isList;
    reduce = yen.lib.reduce.flat;
  };
  imports = [
    { admins = [ "ana" ]; }
    { admins = [ "bo" ]; }
    (
      { yen, admins, ... }:
      {
        yen.aspects.wheel = {
          at = yen.host.web;
          nixos.users.groups.wheel.members = admins;
        };
      }
    )
  ];
}
```

```nix title="result"
{
  groups = {
    wheel = {
      members = [
        "ana"
        "bo"
      ];
    };
  };
}
```

Key names load before any arg has an answer: a key name that reads an arg is an error record. `imports` can read
a sink, such as `inputs`, when modules outside its own imports give it. yen loads such imports in rounds.
`result.modules` shows what each module asks, gives and declares. A cycle in it is `import-loop`, an error record,
not an infinite recursion.


## Types: anything with `check`

A field type is any value with `check = v: bool`. yen does not ship its own type library, and it needs no
nixpkgs. Use what you have:

- `yen.lib.is f`: any predicate, for example `yen.lib.is builtins.isString`.
- nixpkgs types, if you have `lib`: `lib.types.str`, `lib.types.port`. Read the warning below.
- [nix-effects](https://github.com/kleisli-io/nix-effects) types: `Int`, `ListOf`, `Record`, refinements.
- [gen-types](https://github.com/sini/gen) checkers, through their `verify`.

yen keeps validation apart from merging. A type only checks a value. How many values become one is the
sink's `reduce`, its merge strategy: see [Sinks](/behavior/sinks/). A nixpkgs type does both, in `check` and
`merge`. yen calls only `check`.


:::caution[nixpkgs composite types do not check their items]
In nixpkgs, `listOf`, `attrsOf`, `submodule` and `functionTo` check only the outer shape. The items are
checked in `merge`, which yen never calls. So in yen, `lib.types.listOf lib.types.int` accepts a list of
strings:

```nix
(lib.types.listOf lib.types.int).check [ "a" ]          # true
(lib.types.attrsOf lib.types.int).check { x = "a"; }    # true
(lib.types.submodule { options = { }; }).check { y = 1; } # true
(lib.types.functionTo lib.types.int).check (x: "a")     # true
```
Use nixpkgs leaf types (`str`, `int`, `bool`, `port`, `enum`, `nullOr`) freely. For a list or an attrset
whose items matter, use nested fields with a leaf type at each leaf, or a type that checks deep.
:::

nix-effects types check deep, and the kernel can build a check for you: `verified.verify` type-checks an
implementation against its specification and gives a plain Nix function. That function is a check:


```nix
let
  inherit (fx.types) ListOf Int Record hoas verified;
  H = hoas;
  v = verified;
  # String -> [String] -> Bool, verified by the kernel, extracted as a plain Nix function
  strElem = v.verify (H.forall "t" H.string (_: H.forall "xs" (H.listOf H.string) (_: H.bool))) (
    v.fn "t" H.string (t: v.fn "xs" (H.listOf H.string) (xs: v.strElem t xs))
  );
in
{
  yen.kinds.host.fields = {
    ports = ListOf Int; # [ "a" ] fails `check`
    owner = Record { name = fx.types.String; };
    target = yen.lib.is (t: strElem t [ "module" "file" "package" ]); # "fleet" fails `check`
  };
}
```

A gen-types checker has `verify`, which gives `null` or the reason a value fails. Its `check` follows the
nixpkgs protocol and is not `v: bool`, so give yen a check made from `verify`:


```nix
yen.kinds.host.fields.ports = yen.lib.is (v: (gen.listOf gen.int).verify v == null);
```

## Each NixOS pattern, in yen

The kinds hold what NixOS `options` hold. The instances hold what `config` holds:


```nix title="modules/kinds.nix"
# NixOS `options` become kind fields. A field type is anything with `check`: here nixpkgs types and yen.lib.is.
{ yen, lib, ... }:
{
  yen.kinds.fleet = {
    spawns.host = _: yen.host;
  };
  yen.kinds.host = {
    fields = {
      addr = lib.types.str;
      firewall.enable = yen.lib.opt lib.types.bool false; # mkEnableOption: a nested field with a default
      firewall.ports = yen.lib.opt (lib.types.listOf lib.types.port) [ ]; # checks the list, not its items
    };
    spawns.user = h: lib.filterAttrs (_: u: yen.lib.same u.on h) yen.user;
    sinks.nixos.reduce = yen.lib.reduce.merge;
  };
  # attrsOf (submodule { … }) in NixOS: here a kind, whose instances have names, refs and their own errors
  yen.kinds.user.fields = {
    on = yen.kinds.host;
    shell = yen.lib.opt lib.types.str "bash";
  };
}
```

```nix title="modules/fleet.nix"
# NixOS `config` becomes instance data, and `mkIf` becomes `at`.
{ yen, ... }:
{
  yen.fleet.main = { };
  yen.flake = { }; # no flake outputs: this page reads the eval result
  yen.host = {
    web = {
      addr = "10.0.0.1";
      firewall.enable = true;
      firewall.ports = [ 443 ];
    };
    db.addr = "10.0.0.2";
  };
  yen.user.ana.on = yen.host.web;
  yen.aspects.firewall = {
    # mkIf config.firewall.enable. `at` runs at every scope: guard with the kind, then read the field
    at = yen.lib.all [
      yen.kinds.host
      (s: s.firewall.enable)
    ];
    nixos =
      { host, ... }:
      {
        networking.firewall.allowedTCPPorts = host.firewall.ports;
      };
  };
}
```

| NixOS | yen |
|---|---|
| `options.x = mkOption { type; default; }` | `yen.kinds.K.fields.x = yen.lib.opt type default` |
| a top-level option that many modules set, such as `flake.lib` | a module sink: `yen.sinks.x = { of = type; reduce = …; }`, then `x = v;` in each module |
| `mkEnableOption` | a nested field: `fields.firewall.enable = yen.lib.opt lib.types.bool false` |
| `default = f config` | `yen.lib.derive type f`: see [Types](/model/types/) |
| `config.x = v` | instance data: `yen.host.web.x = v` |
| `mkIf config.firewall.enable` | `at = yen.lib.all [ yen.kinds.host (s: s.firewall.enable) ]` |
| list and attrset options from many modules | a sink with a `reduce`: see [Sinks](/behavior/sinks/) |
| `mkDefault`, `mkForce` | a type default, then the instance value. Two values for one leaf are `two-answers` |
| `assertions` | `yen.invariants`, or an aspect's `errors` key |
| `imports`, `specialArgs` | `imports`, and the sinks of the root module: `inherit inputs lib;` |
| `attrsOf (submodule { … })` | a kind with instances, below |

```nix title="result"
{
  "fleet:main/host:web" = {
    networking = {
      firewall = {
        allowedTCPPorts = [
          443
        ];
      };
    };
  };
}
```

:::note[Guard `at` with the kind]
`at` runs at every scope. `s: s.firewall.enable` alone fails at the fleet scope, which has no `firewall`.
`yen.lib.all [ yen.kinds.host … ]` reads the field only on hosts.
:::

## Submodules

In NixOS, `users.users.<name>` and `services.nginx.virtualHosts.<name>` are `attrsOf (submodule { … })`:
a module inside each value, with its own options. `submoduleWith` adds args and more modules to each one.
Each value is merged into one attrset, and it has no identity outside its parent.

In yen, a named submodule is a kind. `user` above is one: each user is an instance with a name, a ref to
its host (`on = yen.kinds.host`), defaults (`shell`), and its own errors with a path. `spawns` makes each
user a scope under its host, so aspects can be active on users, and queries can find them:


```nix title="result"
[
  "fleet:main"
  "fleet:main/host:db"
  "fleet:main/host:web"
  "fleet:main/host:web/user:ana"
]
```

A submodule with no names, like `services.nginx`, is a nested field. `firewall.enable` and `firewall.ports`
above are one. For how `config` as a fixpoint compares, see [Fixpoints and dependencies](/principles/fixpoints/).
