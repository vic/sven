Each key of an aspect gives one element. For 0 to n elements, or to ask the tree for data, write a component
under `cycle`. As in [Cycle.js](https://cycle.js.org), a component is a function from sources to sinks.
Its sources are `tree`, `scope` and one source for each sink. It returns sinks by name, and `tree` requests.


```nix title="modules/network.nix"
# A component: it reads sources (the tree, the sinks) and writes sinks. It gives 0 to n elements.
{ yen, ... }:
{
  yen.aspects.vm-network = {
    at = yen.lib.has yen.kinds.guest; # every host with a guest
    cycle =
      { tree, ... }:
      let
        vms.children = yen.kinds.guest; # a request: the guest children
      in
      {
        tree = [ vms ];
        bridges = map (g: "br-${g.name}") (builtins.head (tree.select vms)); # one element per guest
        errors = [ ];
      };
  };
}
```

The host has two guests, so the component gives two bridges:


```nix title="result"
{
  server = [
    "br-ci"
    "br-db"
  ];
}
```

## Tree requests

A request is one question. `tree.select request` gives its answers: the request is its own name, so it has no
string to mistype. Bind it in a `let` and use it twice.


| Request | Answer |
|---|---|
| `nearest = yen.kinds.environment` | the nearest scope of that kind |
| `parent = true` | the parent scope |
| `children = predicate` | the children where the predicate holds |
| `scopesOf = instance` | every scope of an instance |
| `holds = predicate` | `true` or `false` at this scope |
| `instances = yen.kinds.host` | every instance of that kind, with its data |
| `graph = true` | the whole fleet: instances with data and the structure queries, for readers of everything like docs and diagrams |

:::note[When to use it]
Most aspects never need `cycle`. Use it when the number of elements depends on the tree, or when a component
reports its own `errors`.
:::

## What an element can read

An element reads its args: its scope, the kinds it asks for, and the values its sinks give. To read another
instance, it asks the tree. It never reads that instance's fields directly. Yen knows what every element reads,
so a change is refused only where it reaches. Here a host asks for every host and counts the other ones:


```nix title="modules/reads.nix"
# A host asks the tree for every host, and counts the other ones.
{ yen, ... }:
{
  yen.aspects.peers = {
    at = yen.kinds.host;
    cycle =
      { tree, scope, ... }:
      let
        hosts.instances = yen.kinds.host;
      in
      {
        tree = [ hosts ];
        out = [
          {
            peers.${scope.name} = builtins.length (
              builtins.filter (h: h.name != scope.name) (builtins.head (tree.select hosts))
            );
          }
        ];
      };
  };
}
```

The fleet has one host, so it has no peers:


```nix title="result"
{
  server = 0;
}
```

An element that reads a field of another instance is refused. The variant below does that. The error names the
fix: "yen.host.server.addr: an aspect reads instance data only through its args: take `host` as an arg, or follow
a ref field of an arg".


```nix title="variants/read-addr.nix"
# An element reads a field of another instance: refused, with the fix.
{ lib, yen, ... }:
{
  yen.kinds.host.fields.addr = lib.types.str;
  yen.host.server.addr = "10.0.0.1";
  yen.aspects.read-addr = {
    at = yen.kinds.host;
    cycle =
      { ... }:
      {
        out = [ { addr.server = yen.host.server.addr; } ];
      };
  };
}
```
