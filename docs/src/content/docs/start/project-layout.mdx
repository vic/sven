sven reads one module. A module is a path, a function or an attrset with three keys: `imports`, `_module.args`
and `sven`. sven does not know what `inputs` or `lib` are. You give them as args, and they flow down the
`imports` tree to every file below.


<FileTree>

- default.nix
- flake.nix
- modules/
  - aspects.nix
  - fleet.nix
  - host.nix
- query.nix

</FileTree>

`modules/` is the fleet. Every file there is a module: put each kind, feature or host in its own file,
and move files freely. File order never changes a result.

## Two entry points


<Tabs>
<TabItem label="flake.nix">

```nix title="flake.nix"
{
  description = "sven: flake and no-flake entry points";

  outputs =
    inputs:
    inputs.sven.lib.mkFlake {
      imports = [ (inputs.import-tree ./modules) ];
      _module.args = {
        inherit inputs;
        inherit (inputs.nixpkgs) lib;
      };
    };

  inputs = {
    sven.url = "github:vic/sven";
    import-tree.url = "github:denful/import-tree";
    nixpkgs.url = "https://nixos.org/channels/nixos-25.05/nixexprs.tar.xz";
  };
}
```

</TabItem>
<TabItem label="default.nix">

```nix title="default.nix"
# Without flakes: every query of the fleet. Pin the sources with npins, niv or fetchTarball.
{
  sven ? builtins.fetchTarball "https://github.com/vic/sven/archive/main.tar.gz",
  nixpkgs ? builtins.fetchTarball "https://nixos.org/channels/nixos-25.05/nixexprs.tar.xz",
  import-tree ? import (
    builtins.fetchTarball "https://github.com/denful/import-tree/archive/main.tar.gz"
  ),
}:
(import sven).lib.eval {
  imports = [ (import-tree ./modules) ];
  _module.args = {
    inputs = { inherit nixpkgs; };
    lib = import "${nixpkgs}/lib";
  };
}
```

</TabItem>
</Tabs>

`mkFlake` gives the flake outputs. `eval` gives every query, `flake` included. Both read the same `modules/`.


```nix title="query.nix"
# Queries on the command line:
#   nix eval --impure --file query.nix errors
#   nix eval --impure --json --file query.nix agent
import ./default.nix { }
```

```sh frame="terminal"
nix eval --impure --file query.nix errors          # [ ] when the fleet is valid
nix eval --impure --file query.nix graph.scopes    # every scope
nix build -f query.nix flake.nixosConfigurations.laptop.config.system.build.toplevel
```

## NixOS without the nixpkgs flake

`nixpkgs.lib.nixosSystem` exists only on the nixpkgs flake. `nixos/lib/eval-config.nix` works with a flake input
and with a plain path, so one host file serves both entry points:


```nix title="modules/host.nix" {7}
# eval-config.nix works with a flake input and with a plain nixpkgs path.
{
  sven,
  lib,
  inputs,
  ...
}:
{
  sven.kinds.host = {
    fields.system = lib.types.str;
    sinks.nixos.out =
      { host, nixos, ... }:
      {
        nixosConfigurations.${host.name} = import "${inputs.nixpkgs}/nixos/lib/eval-config.nix" {
          inherit (host) system;
          modules = nixos;
        };
      };
  };

  sven.host.laptop.system = "x86_64-linux";
}
```

:::caution[Args are explicit]
sven gives a module only `sven` and the `_module.args` above it. A file that asks for `pkgs` at the top level gets an error record:
`pkgs` belongs to NixOS. Ask for it inside a `nixos` element.
:::
