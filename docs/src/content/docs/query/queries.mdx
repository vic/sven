`result = (import yen).lib.eval module` gives a set of queries. Each one is lazy: you pay only for what you read.
`result` exists outside the fleet: in a script, a test, the CLI or an agent. Inside the fleet, see [below](#inside-the-fleet).
Every answer is plain data, so `builtins.toJSON` prints it. This small fleet answers each query below.


```nix title="modules/fleet.nix"
{ yen, lib, ... }:
{
  yen.kinds.fleet = {
    spawns.host = _: yen.host;
    sinks.out.reduce = yen.lib.reduce.merge;
  };
  yen.kinds.host = {
    fields.addr = lib.types.str;
    spawns.user = s: lib.filterAttrs (_: u: yen.lib.same u.on s) yen.user;
    sinks.packages = {
      reduce = yen.lib.reduce.set;
      out =
        { host, packages, ... }:
        {
          packages.${host.name} = packages;
        };
    };
  };
  yen.kinds.user.fields.on = yen.kinds.host;

  yen.fleet.main = { };
  yen.host.web.addr = "10.0.0.1";
  yen.user.ana.on = yen.host.web;
  yen.aspects.git = {
    at = [
      yen.kinds.host
      yen.kinds.user
    ];
    packages = "git";
  };
  yen.aspects.nginx = {
    at = yen.host.web;
    packages = "nginx";
  };
  yen.flake = { out, ... }: out;
}
```

| Query | Answer |
|---|---|
| `errors` | `[ { error; from; code; … } ]`, empty when the fleet is valid |
| `graph` | `{ scopes; edges; }`: every scope and every routed element, with its `origin` |
| `scopes` | the scopes in order |
| `active` | aspect, then scope id, then `true` or `false` |
| `undefined` | aspects that `at` cannot decide (a cycle through `not`) |
| `reduced` | sink, then receiver id, then the value |
| `flake` | the answer of `yen.flake` |
| `data` | every instance's declared fields |
| `schema` | every kind, aspect and invariant, as JSON-safe data |
| `declaredIn path` | the files that answer a declaration path |
| `facts` | the fleet as ground atoms, for Datalog |
| `context id { }` | one scope: parent, children, aspects, what it gives and receives |
| `check` | the invariants: see [Invariants](/query/invariants/) |

## One scope in context

`result.context id { maxEdges; maxAspects; }` is what an agent or a person reads first about a scope.
Each list says how much it shows of how much there is:


```nix title="result"
{
  aspects = {
    items = [
      "git"
      "nginx"
    ];
    truncated = {
      of = 2;
      shown = 2;
    };
  };
  children = [
    "fleet:main/host:web/user:ana"
  ];
  errors = [ ];
  given = {
    items = [
      {
        from = "fleet:main/host:web";
        origin = "aspect git";
        sink = "packages";
        to = "fleet:main/host:web";
      }
      {
        from = "fleet:main/host:web";
        origin = "aspect nginx";
        sink = "packages";
        to = "fleet:main/host:web";
      }
      {
        from = "fleet:main/host:web";
        origin = "sink packages";
        sink = "out";
        to = "fleet:main";
      }
    ];
    truncated = {
      of = 3;
      shown = 3;
    };
  };
  kind = "host";
  name = "web";
  parent = "fleet:main";
  received = {
    items = [
      {
        from = "fleet:main/host:web";
        origin = "aspect git";
        sink = "packages";
        to = "fleet:main/host:web";
      }

  undefined = [ ];
```

## Which aspects reach this host?

Each edge of `graph` has `origin`: the aspect that gave the element. "Which aspects reach `web`" is a filter,
not a registry: `map (e: e.origin) (filter (e: e.to == "fleet:main/host:web") result.graph.edges)`.


```sh frame="terminal"
nix eval --impure --file query.nix errors
nix eval --impure --json --file query.nix graph
nix eval --impure --expr '(import ./query.nix).context "fleet:main/host:web" { }'
```

:::note[query.nix]
The commands above use a `query.nix` that returns `eval` of your modules. See [Project layout](/start/project-layout/).
:::

## Inside the fleet

A module never gets `result`: the fleet is what `result` is computed from. An element reads results through its args
and `yen.lib`, where it runs:


| To read | Inside the fleet |
|---|---|
| a sink's reduced value | a sink arg: `{ packages, ... }:` gets the value at the nearest receiver of `packages` |
| the nearest scope of a kind | a kind arg: `{ host, ... }:` |
| this scope, its parent | `{ scope, ... }:`, then `scope.parent` |
| the children where a predicate holds | `yen.lib.children p scope` |
| whether a predicate holds here | `yen.lib.holds p scope` |
| the scopes of an instance | `yen.lib.scopesOf instance` |
| the whole fleet | `yen.lib.graph`, `yen.lib.schema`, `yen.lib.declaredIn`, `yen.lib.labels` |

```nix title="variants/inside.nix"
# Inside the fleet there is no `result`. An element reads results through its args and `yen.lib`.
{ yen, ... }:
{
  yen.aspects.inside = {
    at = yen.kinds.host;
    out =
      {
        scope,
        host,
        packages,
        ...
      }:
      {
        inside.${host.name} = {
          inherit packages; # a sink arg: the reduced value of `packages` at its receiver
          parent = scope.parent.id;
          users = map (u: u.name) (yen.lib.children yen.kinds.user scope);
          nginx = yen.lib.holds yen.aspects.nginx scope;
        };
      };
  };
}
```

```nix title="result"
{
  web = {
    nginx = true;
    packages = [
      "git"
      "nginx"
    ];
    parent = "fleet:main";
    users = [
      "ana"
    ];
  };
}
```

:::note[Not inside]
`errors`, `check`, `context`, `explain` and `impact` read the errors, and an element that reads the errors
could change them. They exist only on `result`. A stored query gets `result` when it is asked from outside:
see [Stored queries](/query/stored-queries/). A [cycle](/concepts/cycle/) also asks the tree with `tree`.
:::
